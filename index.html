文本情感分析

多语言情感模型（5 档：极差 → 极好），中英文均可。首次运行下载约 100–200MB，之后走浏览器缓存。

语义相似度

用 all-MiniLM-L6-v2 把两句话编码成向量，再算余弦相似度。首次运行下载约 20–30MB。

零样本分类

无需训练：给文本和候选标签，模型直接判断最匹配类别（英文效果最佳）。首次运行下载约 40–60MB。

本地流式对话 · 实验性

在浏览器内运行 Qwen2.5-0.5B-Instruct（q4 量化，约 300–450MB），逐 token 流式输出。首次加载较慢，建议优先用 WebGPU。

技术实现

推理链路Tokenizer（WASM）→ ONNX Runtime Web（WebGPU / WASM）→ 后处理；模型按 HuggingFace 目录结构按需拉取。
三级降级WebGPU(fp16/q4f16) → WebGPU(q8/q4) → WASM(q8/q4)，任一环节失败自动回退并提示。
缓存与网络Cache Storage 持久化模型；jsDelivr / esm.sh / unpkg 多 CDN 容错，模型源可在国内镜像与官方间切换。
性能观测记录首次加载耗时、单次推理耗时与连续 5 次基准；对话页统计首 token 延迟与生成速度。
  • 为什么放浏览器：隐私（文本不出设备）、零服务端 GPU 成本、低延迟、可离线；代价是首次下载与前端内存占用。
  • 量化与 dtype：WASM 用 q8/q4 控制体积；WebGPU 优先 fp16/q4f16 利用硬件能力，精度损失在演示任务上可接受。
  • 局限：模型越大首次加载越久；移动端内存敏感；WebGPU 覆盖率仍不完整；量化会带来一定效果损失。
